# Top-p 行并行：4K ABBA 复核与下一步

> 2026-11-03更新：16K最终非劣化审核通过（2557.84 tok/s）；本报告原结论保留其当时状态，最终组合与收尾见[最终技术报告](final_optimization_report_20261103.md)。

固定代码、固定 A1→B1→B2→A2 顺序的官方 4K 对照得到：关闭开关的两个会话均值为 **3539.200 total tok/s**，开启为 **3687.315 total tok/s**，增量 **+4.185%**；TPOT 从 **84.115 ms** 降到 **80.880 ms（-3.846%）**。16 轮共 4096 请求全部成功，两次固定配对均有收益，预登记工程门槛全部通过。

测量完成于 2026-10-30 21:13，独立审核完成于 2026-11-02 16:16。结果支持继续做 16K 验证。当前选定配置仍为 EXP20，top-p 在源码中默认关闭；候选 16K 尚未测量，完整模型任务精度按用户要求暂缓。

## 优化前后：改变行并行度，不改变筛选算法

原 top-p launcher 为 min(16, B) 个 program；B64 时，每个 program 串行处理四行。候选用 min(64, B) 个 program，B64 时每个 program 处理一行。保留原 top-k/top-p JIT、tile、查表、warps/stages、筛选和随机数语义。此次没有新增算子融合。

仅在已验证的 BI-V150 单卡、FP32、词表 130560、B17..64、top-p-only 及支持的 stride 上启用；其他情况回退。原 RoPE+KV 融合、GQA decode 八行布局/分页读取、prefill 页号广播、MLP 布局和调度保持。scratch 从 16 行扩到共享的 64 行，名义增量 23.90625 MiB；是否影响 KV 池必须看引擎实测，不能直接推算。

接线经真实 general-plugin 注册链路确认，base/sampler 两个别名一致。此前已完成 39 项设备入口/Graph/fallback 检查，以及真实模型 B17..64 各两次、共 96 次精确 mask/RNG 检查。正式计时关闭 shadow。这些算子检查不等于完整模型任务精度。

B64 单算子截断阶段微基准耗时下降 66.73%；本次整模吞吐提升 4.185%。两者口径不同，整模还包含 prefill、投影、小 batch 和服务开销。

## 固定代码与测评口径

- 推理插件：c50b5f0526e8112c72f1de918487300cf7376378；FlagGems：de958ddfc4deeb43d6c94bb8652a3d4d3bc905fe。
- A 关闭 VLLM_FL_TOPP_ROW_PARALLEL，B 开启；两者 shadow=0、arm 文件为空、MLP 布局改动关闭。
- 同一冻结工作区，每个会话新服务、新 VLLM/Triton/Inductor 缓存，全局 GPU 锁串行。
- 官方 [4096,1024,64,256]，random 数据、默认采样、ignore-eos、FULL_DECODE_ONLY、gpu-memory-utilization=0.85、max-model-len=131072。
- 每个会话四轮，只按官方规则弃首轮。先求各会话官方 summary，再对同开关的两个会话等权平均。没有混入 EXP27/28，也没有额外排除慢轮。

A 虽沿用 EXP20 的计算路径，实际源码提交仍是 c50b5f0，不能把 A 描述为直接运行 ce19f93。
