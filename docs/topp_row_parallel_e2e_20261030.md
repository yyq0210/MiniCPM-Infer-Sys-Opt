## 优化前后与接入证据

原vLLM launcher在16个SM上启动min(16,B)个program；B64时每个program循环处理4行logits。候选启动min(64,B)，B64时每个program处理1行，并将共享scratch缓存从16行扩至64行。调用同一个原始top-k/top-p JIT内核，tile8192/4096、表、warps/stages、筛选算法和随机数/采样定义保持；这是行并行调度调整，没有新增算子融合。

适用范围保持BI-V150单GPU、FP32、V130560、B17..64、top-p-only及受支持stride；其他条件回退原路径。B<=16没有此项加速。原RoPE+KV融合、GQA decode8行分页读取、prefill页号广播及原MLP布局保留。正式缓存重新核验64个decode和64个prefill GQA核、42个MLP模块/84个权重节点、42次RoPE+KV图融合以及35个FULL捕获尺寸。

正式服务无shadow比较日志，实际top-p grid64出现，最大已记录候选调用计数16,384；三个top-p编译变体的元数据与TTIR哈希复核通过。GPU入口39项检查已通过。之前独立的真实模型诊断256请求零失败，B17..64各两次、共96次mask逐元素和RNG检查通过，包含真实B64/p=.95；诊断数据不并入性能。

微基准B64截断阶段平均耗时下降66.73%，整模只呈现约3%的历史比较改善，两者量纲和覆盖范围不同：官方负载含prefill、其他投影、不同batch、调度和传输，小batch还会回退。此前NONE模式窗口的采样占比不能直接当生产FULL整程占比，当前没有定位出精确的整程收益分解。
