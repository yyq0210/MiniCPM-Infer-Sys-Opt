# 每次优化的记录方式

每个实验目录至少包括：目标和假设、代码基线、具体改动、完整命令、输入形状/数据集、运行时环境、原始结果、正确性、性能、失败记录、结论和下一步。可以先用 `scripts/new_experiment.py` 创建记录。

每一步填写实际发生的动作。无法从日志恢复的时间标为“时间未独立记录”，不可编造精确时间。新测量放入新目录或新 run 编号；旧日志保持不变。进行安装或修改配置时保存修改前后状态。

结果表使用相同工作负载和计时口径，明确 warmup、重复次数、汇总方法及噪声。候选配置 sweep 中的最快值需要标明是本轮选优，不作为未经复测的普遍结论。

正式性能实验结束后用 `scripts/collect_baseline.py` 采集结果。该脚本复制快照并校验两个场景和八轮原始记录，生成 STATUS.md；运行中的结果标为 pending。`--wait` 模式只等待本轮已有作业结束并归档，不启动新 benchmark，也不定时推送。

发布前执行以下检查：

1. 确认原始日志和汇总表可对应，记录代码 commit SHA 与内容哈希。
2. 正确区分未运行、运行中、失败和完成；不能把脚本退出 0 当作全部评测成功。
3. 检查 staged 文件，排除权重、数据集、缓存、凭据、SSH 信息和机器标识。
4. 将源码、实验记录分别提交到指定仓库，记录远端分支 SHA 与 PR 链接。
