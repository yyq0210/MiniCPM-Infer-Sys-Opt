## 假设及实际路径

保持权重数值，加载时一次把 `[N,K]` 权重存储从 stride `(K,1)` 变为 `(1,N)`，可能改善完整 MLP 的执行时间。需要确认两个 GEMM 的收益能覆盖实际 SwiGLU 以及中间张量开销。

LlamaMLP.forward 源码路径是 gate_up_proj → SiluAndMul → down_proj。2026-10-28 CPU 路由预检查没有找到预期的 CachedOp 首次使用日志，停止了该准备尝试，未启动 GPU 工作。进一步检查 EXP20 正式 4K 的真实计算图，确认第 707/711/713/716 行为原生 linear、forward_native 的 F.silu、乘法、原生 linear；服务只有 attention_backend 与 rotary_embedding 的 default.flagos 记录。因此不能把插件中存在的 SiluAndMulFL 类当作实际生效路径。

生产 Inductor 缓存仅发现一种 SwiGLU 生成源：triton_poi_fused_mul_silu_slice_1，动态 xnumel、无硬编码 M，源字符串 SHA256 为 2077eeed3cb635af436273a4ca3c69e6fb2d32e303bbf50b739950086df2cb6a。完整子图采用 native linear → 从实际服务提取的同一生成内核 → native linear，通过独立缓存编译该内核并计时完整路径。只提取该内核源和来源哈希，不发布整个缓存。记录 runtime callable 与源哈希；不把未编译的 F.silu 两个 eager kernel 作为生产激活实现。

该生成内核在 FP32 内计算 silu 和乘法，乘积写回时舍入为 BF16；中间 silu 没有单独的 BF16 舍入。FP16 回归只对提取源的 signature 元素类型和内核名字作明确替换，其他计算与 launch metadata 保持，且必须记录这是派生的回归内核，非生产 BF16 缓存。原生 linear 与生成模块的 extern_kernels.mm 对应；本轮仍是随机权重子图诊断，不是完整服务请求重放。在真实引擎接入阶段还需探针核对模型加载后的实际 weight stride。

## 固定比较

- 四种布局：原布局、仅 gate/up 重排、仅 down 重排、二者重排。原布局为每个候选的夹测参照。
- M：1、4、8、16、30、32、64、128、512、2048。M8/16 为生产尾部主目标；M30 仅作 NONE 诊断。
- 独立随机种子：202610261、202610262、202610263；权重标准差 0.02。
- hot 使用同一组权重；weights8 轮换八组独立的 gate/up 与 down 权重。这只是缓存敏感性代理，不是 42 层模型请求重放。
- 每个候选采用旧/新/旧夹测，7 个样本，每样本 8 次 Graph 子图调用。三候选×十种 M×两模式×三个种子，共 180 个计时点。
- 三个种子循环调整候选顺序，完整保留每个种子、形状和模式的结果，不按中途性能停止或删点。
- 计时完整 gate/up→实际 SwiGLU→down，不将孤立 GEMM 时间直接相加。不把一次性重排放在逐次子图计时中；加载成本及临时内存另记。

## 数值与 Graph 检查

使用固定 `atol=0.03, rtol=0.03` 比较完整子图候选和原布局，记录绝对与相对误差。FP32 参考必须明确 BF16/FP16 的中间舍入边界，分别检查 gate/up、SwiGLU 和 down；不能把分段参考说成无中间舍入的整模 FP32 精度。

基础 BF16 检查覆盖三个种子×十种 M×三个候选，共 90 项。独立 FP16 种子 202610264，M1/8/16/512/2048×三个候选，共 15 项。另对 BF16 M8/2048 的零输入、常量输入分别检查三个候选，共 12 项，总计 117 项。

每项检查需改变输入和两组权重后重放 Graph，与同布局 eager 输出严格一致；验证输出 shape、连续性、权重值一致及布局正确。若原布局或候选不满足预定数值门槛，保留失败并解释，不临时放宽阈值继续宣称通过。用户暂缓的整模任务精度与这些算子检查分开记录。

## 接受标准

每个种子中，候选在 M8/16 的两种模式都至少降低 5% 完整子图耗时，其余所有点回归不超过 3%，每次夹测绝对漂移不超过 3%；全部数值与 Graph 检查通过后才进入集成候选。保存未达标结果，不以单个最佳点替代完整覆盖。

如果多个候选通过，比较全部主目标点的平均耗时比；差距不足一个百分点时优先选择重排矩阵更少的方案。独立审核全部样本、中位数、公式、覆盖集合、路由及脚本哈希后才作决定。
